## Overview

CMS Law Frontend is an enterprise Content Management System frontend application built with React 19, Vite, TypeScript, TanStack Router, TanStack Form, Tailwind CSS v4, and Puck editor (`README.md:1-4`).

The application is designed around a modular, feature-oriented structure (`src/features/`) with file-based routing (`src/routes/`), strict TypeScript compilation (`tsconfig.app.json:20-28`), and conventional commit enforcement via Husky git hooks (`.husky/`, `package.json:22-34`). Currently, core visual page authoring via Puck and a basic authentication UI are implemented; other CMS domain modules (layout shells, UI primitives, media asset management, content management) exist as scaffolded directories.

## Data Flow

### 1. Navigation Flow

- User visits the web app (`/`).
- TanStack Router matches routes file-based via `src/routeTree.gen.ts`.
- Preloading is enabled by default on intent (`src/app/router.tsx:6`).
- Navigation links use type-safe `<Link to="...">` components (`src/routes/index.tsx:8-20`, `src/routes/_authenticated/dashboard.tsx:6-11`, `src/routes/_authenticated/preview.tsx:9-15`).

### 2. Authentication Flow (Current State)

- User opens `/login` (`src/routes/login.tsx:4-14`).
- Input values are bound to `@tanstack/react-form` form fields (`src/features/auth/components/SignInForm.tsx:34-86`).
- Form submission validates input against `loginSchema` (`src/features/auth/schemas.ts:3-6`).
- On validation success, form prints values to `console.log` and executes client-side redirect `navigate({ to: '/dashboard' })` (`src/features/auth/components/SignInForm.tsx:18-21`).
- _Note:_ No session token, cookie, or backend authentication request is dispatched.

### 3. Page Editor & Preview Flow

- User navigates to `/editor` (`src/routes/_authenticated/editor.tsx:4-6`).
- `<PuckEditor>` loads static `initialPageData` (`src/features/editor/config/puck-config.tsx:1179-1248`) and exposes the interactive block canvas.
- Clicking "Preview" invokes `navigate({ to: '/preview' })` (`src/features/editor/components/PuckEditor.tsx:23-25`).
- `/preview` mounts `<PuckPageRenderer>`, which independently renders static `initialPageData` (`src/features/editor/components/PuckPageRenderer.tsx:7`).
- _Note:_ In-memory changes made in the editor canvas are not synchronized to preview or persisted to storage.

## Conventions

- **Path Aliasing:** `@/*` maps directly to `./src/*` (`tsconfig.app.json:16-18`, `vite.config.ts:10-12`).
- **Type Imports:** Enforced strict inline type imports (`@typescript-eslint/consistent-type-imports`, `eslint.config.js:35-38`).
- **File Organization:** Feature-first structure under `src/features/<feature>/` (`components/`, `config/`, `types.ts`, `schemas.ts`). Shared code under `src/components/`, `src/hooks/`, `src/lib/`, `src/types/`.
- **CSS Styling:** Tailwind CSS v4 via `@tailwindcss/vite` (`vite.config.ts:8`, `src/index.css:1`). Class names conditionally combined via `cn(...)` (`src/lib/utils.ts:4-6`).
- **Git Commits:** Conventional Commits enforced via Commitlint and Husky (`.commitlintrc.cjs:1-14`, `.husky/commit-msg:1`). Types: `feat`, `fix`, `docs`, `style`, `chore`, `refactor`, `test`, `revert`.
- **Branch Naming:** Validated on push (`.husky/pre-push:1`, `package.json:31-34`) matching `^(main|develop|staging)$|^(feature|bug|release|setup|hotfix|refactor)/[0-9]+-[a-z0-9]+(_[a-z0-9]+)*$`.
- **Testing:** No testing conventions or test runners are currently configured in `package.json`.
